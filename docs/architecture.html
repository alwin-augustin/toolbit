Section 01 · Context

At a glance

Toolbit is a static browser workbench: no backend, no accounts. A React single-page app serves 42 developer utilities inside one document workspace. Everything that can run locally does; the only network traffic a tool may cause is the request the user explicitly sends, plus sanitized product telemetry.

Section 02 · Rules of the game

Principles

Local-first, honestly labelled

Transforms run on the device. Network tools say so next to Send/Connect — no unconditional “local-only” badge where traffic happens.

One canonical semantic per tool

UI, workers and recipes share the same pure functions in core/tool-contract. Same name and options, same result everywhere.

Session-only payloads

Tab content lives in memory. Persistence strips payloads; saves and history entries are explicit, guarded acts — never side effects of typing.

Depth over duplication

Behaviour concentrates behind small interfaces (one editor, one store, one contract module). Callers get leverage; fixes land once, everywhere.

Layer 01 · app/

Application shell

Owns composition and navigation, never transform logic. WorkspaceShell renders the grid (sidebar, topbar with search and document tabs, screen outlet, dialogs, toast). router.tsx maps URLs to screens and guarantees every tool route has a backing document; unknown slugs fall through to Start.

Module Interface (what callers learn) Seam / notes
app/router.tsx Tool routes render a workspace; /, /library, /saved, /history, /settings render screens Deep: one ToolRoute covers migrated, bespoke and routed tools
app/shell/ Sidebar nav, ⌘K search dialog, document tabs, save dialog, toast — all keyboard reachable Global keys live in the shell; screens stay dumb about chrome
app/screens/ Start (smart paste + pins + sessions), Tools catalog, Saved, History (opt-in), Settings Screens read stores; they never own documents
app/components/, app/pages/ Error boundaries, install prompt, offline indicator, legal/marketing pages Kept out of the workbench render path

Layer 02 · features/tools/

The 42 tools, in two shapes

Tools come in exactly two shapes. Spec-driven tools (12) declare actions, options and a run() over canonical contracts and render in the generic WorkspaceScreen — input/output panes, toolbar, error banner, copy/download, “use result in…”, save. Bespoke tools (30) own a screen for layouts a rectangle cannot express: multi-field results, live previews, builders, network consoles.

specs.ts — 12 tools

json · base64 · timestamp · url · yaml · csv→json · sql · css · graphql · js-minify · html-escape · strip-whitespace. Each spec: actions, option schema (inline selects vs Options popover), defaults, run(input, params, mode), accuracy notes.

custom-screens.tsx — 30 tools

A registry mapping tool id → screen (cron registers twice: parser + generator). Screens reuse shell styles, CodeEditor and document hooks — bespoke layout, shared seams.

Adding a tool? If it fits input → action → output, add a spec (no new screen). If it needs its own layout, add a folder features/tools/<tool-id>/ with the screen plus pure helpers, register it, and cover the helpers with unit tests. Both paths reuse the contract layer — never implement a transform twice.

Layer 03 · shared/

Shared seams

The small interfaces everything else stands on. Each of these passes the deletion test: remove it and complexity reappears across dozens of callers.

Module Depth (interface → behaviour)
shared/CodeEditor.tsx One editor behind value · onChange · language · wrap · readOnly · label: CodeMirror 6, JSON highlighting, 100 KB bounded previews with full-output copy, undo history, status reporting.
shared/workspace-store.ts Zustand tabs: openDocument · patchDocument · closeTab · reopen. The persist seam strips payloads, so tab chrome survives refresh while content stays session-only.
shared/document-state.tsx useDocumentField · useDocumentOptions · useSessionDocumentState — per-document state scoped by DocumentContext, serializable-only, garbage-collected with tabs.
shared/workbench{,-memory,-actions}.ts Doc-state helpers, ephemeral saved/runs/settings/toast, and shared open/restore navigation used by every screen.
shared/ds/ Typed design primitives + self-hosted Geist/JetBrains Mono + CSS-first tokens. The single visual language; no second component library.

Layer 04 · core/

The engine room

Pure, UI-free, and therefore reusable from screens, workers, recipes and tests. core/ imports nothing above it — that one-way seam is what makes “same name, same semantics” enforceable rather than aspirational.

Module Depth (interface → behaviour)
core/tool-contract.ts 14 versioned DEFINITIONS (parse · size-guard · abort-aware transform · option serialization) plus pure transforms; 10 MB input limit; unsafe-integer warnings; compatible() gates handoffs.
core/execute-tool.ts + tool-worker.ts One dispatcher: small inputs run inline, large inputs move to a disposable worker with timeout + abort. Callers never choose threads.
core/tool-policy.ts getToolPolicy · canPersistTool · canShareTool — sensitivity (normal/personal/secret), network posture, history defaults. Central guard, not per-screen folklore.
core/telemetry/ Fail-closed allowlists: event names, enum-bounded properties, sanitized values. 15 events (open, transform, copy, restore, rerun…). No payloads, tokens, URLs or content-derived identifiers — ever.
core/smart-detect.ts Deterministic content detection returning actions (“Format JSON”), not destinations — with reasons, never silent rerouting.
core/recipes.ts · workspace-db · history-db · workspace-schema · preferences Settings-only recipes (validated, deterministic, cancellable); guarded history; explicit include-data saves; schema-migrated workspace restore.

Layers 05–06 · content/ · platform/

Catalog, content and platform

content/tools.config.ts

The 42-entry catalog: id, name, description, category, path, keywords. Single source for routes, search, pins and the SEO generator. No components, no logic.

content/seo/

Shared metadata + per-route descriptors feeding prerendered marketing/tool pages and the sitemap.

platform/service-worker.ts

Registration side of the Workbox offline cache: app shell, tool routes and generated pages work without network after first visit.

platform/posthog.ts

Analytics bootstrap only — all event rules live in core/telemetry. No SDK magic, explicit transport, no retry queue.

Section 05 · URLs

Routing

Tool URLs are stable, shareable entry points (/json-formatter, not /app/…). Opening a tool route guarantees a backing document: the router reuses the most recent tab or creates one. Payloads are never encoded into URLs — sharing is an explicit act, not a side effect of typing.

Route Renders
/ Start — smart paste, pins, sessions
/library · /saved · /history · /settings Catalog · sessions/recipes/snippets · opt-in runs · preferences
/<tool-id> × 42 Spec workspace or bespoke screen for that tool
/about · /privacy · /terms Marketing and legal pages (outside the shell)
/app/* 301 to the equivalent root URL

Section 07 · Language

Glossary

One word, one meaning. These definitions describe the product language only — deliberately free of implementation details.

Document
One working instance of a tool, with its own input, options and result. Several documents may use the same tool.
Session
A named collection of open documents, saved deliberately. Sessions never capture data implicitly.
Recipe
An ordered, executable transformation with fixed options. Each run supplies fresh input; the recipe itself stores none.
Snippet
A reusable piece of non-secret text, saved explicitly for reuse in future tasks.
History run
A past execution with its original input and result. Recording is opt-in; restoring opens a new document.
Handoff (“use result in…”)
Carrying one tool’s result into another tool as new input. A one-off transfer, not a saved pipeline.
Smart paste
Deterministic detection that suggests actions (“Format JSON”) with reasons — never silent rerouting, never overwriting.
Session-only
Held in memory for the current visit. Refreshing the page ends it; nothing is written to disk.

Section 08 · Load-bearing choices

Decisions

Only decisions that are hard to reverse, surprising without context, and the result of a real trade-off are recorded here.

Canonical contracts shared by UI, workers and recipes keeps semantics single

Alternative: each surface implements its own transforms (faster to write, drifts immediately — e.g. a validator that formats instead of validating). Cost of reversal: every recipe and worker call-site. Hence pure, versioned definitions with size guards and abort support.

Payloads stripped on persist; saves explicit trust boundary

Alternative: persist everything for convenience (leaks secrets into disk, history and exports by default). Tab chrome restores; content never does unless the user says so, per tool-policy sensitivity.

No payload in URLs trust boundary

Alternative: encode state into shareable links (fragments persist in history, get copied, and read as encryption to non-experts). Sharing is an explicit action with a preview of what leaves the device.

Terser lazy-loaded with a global shim surprising

The JS minifier is a Node-oriented package whose dependency tree references Node’s global, which crashed app boot in production. It loads on demand (out of the main chunk) with global → globalThis defined at build time.

System-following theme with explicit override preference

Theme resolves from one seam both sides share: a plain localStorage key read pre-paint by theme-init.js and owned afterwards by shared/theme.ts. Unset means follow the OS; Settings (Light/Dark/System) and the Topbar toggle write explicit choices. Shell colors resolve through --wb-* tokens with light overrides — no literal colors in rules.

IndexedDB for history and saved work scale + guards

Alternative: localStorage JSON blobs (simpler, but unbounded and unindexed). IndexedDB gives bounded stores (200 entries / 20 per tool), retention pruning, and central sensitivity guards at the write seam.

Section 09 · Working agreement

Conventions

Code

  • TypeScript strict, import type where required; Prettier 100 cols, single quotes; ESLint zero warnings.
  • Absolute imports via @/; no relative imports leaving a folder.
  • Pure helpers exported beside screens for unit tests; screens stay thin.
  • Icons: Tabler only. Styles: existing shell/design-system classes; no new CSS without a token.

Tests

  • Contract vectors (workbench-tools), per-tool helper suites (workbench-custom-*), shell journeys, router wiring.
  • E2E matrix covers install, offline, axe, storage/clipboard denial, zoom, handoff.
  • Never assert engine-specific error text (e.g. V8 vs WebKit JSON messages).
  • Knip before removing files; confirm reachability for runtime-loaded workers.
